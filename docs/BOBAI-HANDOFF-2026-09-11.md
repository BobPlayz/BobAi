# BobAI handoff — 2026-09-12

This pass adds the repository-side local voice and media layer requested for BobAI. BobVoice is now the local TTS orchestration layer around a Piper-compatible executable and local ONNX voice model, with bounded text and WAV output, configurable executable/model paths, command availability reporting, temporary-file cleanup, and shell-free process execution. The existing authenticated `/voice` API now uses this local implementation by default while preserving the provider hook as an optional compatibility override.

Speech-to-text is now implemented through whisper.cpp. BobAI accepts bounded base64 audio at the authenticated voice transcription endpoint, normalizes arbitrary supported input through FFmpeg to mono 16 kHz PCM WAV, invokes `whisper-cli` with a configured model, reads the generated transcript, and cleans up all temporary files. FFmpeg and ffprobe are also exposed through an authenticated `/ffmpeg` API for bounded probing and explicit-format media conversion. Conversion strips metadata by default, supports a constrained format allowlist, optionally extracts audio, and supports bounded image scaling. All local command execution uses Node child-process APIs with `shell:false`, explicit argument arrays, timeouts, and output limits.

The root and API environment templates now document the four local command paths plus Piper and Whisper model paths, with PATH-friendly defaults and no cloud media credentials. The API package includes focused command-builder tests and the root `npm test` command now runs both the existing security suite and the local media contract suite. The repository contains `docs/LOCAL_MEDIA.md` describing setup, endpoints, limits, and the exact boundary between repository implementation and installed binaries/model weights.

A follow-up hardening pass normalized nullable options objects before local media execution so malformed JSON option values cannot cause an avoidable runtime exception. The repository-side implementation is therefore self-contained and does not require a cloud provider, but actual speech/media execution remains dependent on installed binaries and model weights.

The new code has not been executed in this tool environment, so this pass does not claim that Piper, whisper.cpp, FFmpeg, or their model weights are installed or working on the user's Windows machine. The remaining verification is therefore environment-specific: install the three runtimes, install a compatible Piper voice and whisper.cpp model, configure model paths if they are not on defaults, run the repository build/tests, query the local status endpoints, and perform real synthesis, transcription, probing, and conversion requests. No cloud provider credential is required for these features.

BobHS remains a separate self-hosted foundation. Its production ingress/TLS, persistent state, capacity scheduling, volumes, registry, rolling deployments, logs, backups, domains, failover, and runtime verification remain explicitly unclaimed. Before every future commit, roadmap.md and this handoff must both be updated. roadmap.md must remain checklist-only and this handoff must remain paragraph-only. Unverified build, test, provider, deployment, runtime, hardware, and environment work must never be represented as completed merely because the repository contains the corresponding implementation.
