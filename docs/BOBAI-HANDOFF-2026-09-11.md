# BobAI handoff — 2026-09-13

BobAI now presents one user-facing native model rather than separate named model personalities. The same model decides whether to answer directly or request tools, while the tool registry remains an independent policy boundary for permissions, approvals, validation, provider availability, and bounded execution.

The chat path now runs a bounded model-tool loop: Bob selects tools, approved tools execute through a centralized executor registry, tool results are returned as explicitly untrusted data to the same model, and Bob can select another tool or produce the final response. Every currently registered tool has a repository-side executor entry. Approval-required tools stop before execution unless a valid short-lived approval is supplied. Tool execution now has a repository-side global disable switch, provider response bodies are read with hard byte limits instead of loading an unbounded body first, browser and website-test targets reject embedded URL credentials, and production browser targets require HTTPS.

The provider safety changes are repository-side safeguards only. Real provider behavior, DNS/network policy of provider services, sandbox isolation of coding workers, target hardware, native media builds, production ingress/database wiring, and external security testing still require the target environment and must not be marked verified from source inspection alone.

The repository tree was corrected after a transient contents-API write replaced the new loop file; the canonical main branch now restores the complete loop implementation and keeps the roadmap and handoff aligned. Future changes must inspect the current main branch first and update roadmap.md and this handoff together. Never invent files, features, test results, model quality, or environment results.
