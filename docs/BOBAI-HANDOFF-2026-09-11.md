# BobAI handoff — 2026-09-12

This pass replaces the previous Ollama-backed BobAI chat path with a BobAI-owned native model architecture. Bob-0.1-native is a decoder-only transformer defined in the repository and executed directly by Node.js through the native model runtime. The runtime loads a portable model.bob file, performs embeddings, positional encoding, causal multi-head attention, feed-forward layers, layer normalization, and token generation without spawning Ollama or contacting an inference server. Model profiles for Bob, the coding agents, and the fast coding profile now all resolve to the same native model contract.

The training kit was also changed from LoRA fine-tuning of a third-party foundation model to training Bob-0.1-native from scratch. The repository now contains the architecture, tokenizer, trainer, portable weight exporter, evaluator, native model configuration, and root model lifecycle commands. Training uses the existing sanitized JSONL envelope and preserves the explicit eligibility and consent boundary, secret and basic PII sanitization, deterministic deduplication, and held-out validation/test splits. Generated model weights are intentionally ignored by git because they are deployment artifacts rather than source code. The included starter dataset is deliberately small and is a development proof, not a frontier-quality language model.

The Node API now exposes an authenticated native model status route and reports the native model as unavailable when model.bob has not been generated, rather than silently falling back to another model provider. Readiness now includes native model availability, so a deployment cannot report fully ready while its configured chat model is missing. No Ollama environment variable, URL, executable, or model name remains in the native chat contract.

The local media work remains separate from the AI model runtime. BobVoice, whisper.cpp, and FFmpeg are still local media engines invoked through BobAI's bounded process layer because those engines are not the language model. Their integration is shell-free, argument-bounded, timeout-bounded, and documented, but their external binaries and model weights still require target-machine installation. This is deliberately not represented as a native replacement for those codec and speech engines.

The repository-side training architecture is complete enough for the next model-data phase: add a substantially larger eligible dataset, run preparation, train Bob-0.1-native or a later architecture version, evaluate it, and place the resulting model.bob in the configured native model directory. The small architecture is intentionally compatible with modest CPU/RAM hardware, while the training interface can later scale dimensions and depth for stronger hardware without changing BobAI's chat, memory, tools, agents, or UI contracts.

BobHS and the other platform subsystems remain bounded by the same rule as before: unverified production ingress, shared durable orchestration, external deployment infrastructure, real provider callbacks, target-hardware performance, and end-to-end runtime verification cannot be claimed from repository inspection alone. Before every future commit, roadmap.md and this handoff must both be updated. roadmap.md remains checklist-only and this handoff remains paragraph-only.
