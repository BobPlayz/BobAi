BobAI remains a single user-facing assistant with a central tool-policy boundary, a compact development model, and a separate scalable production-model path. The main runtime exposes `computer`, `paint`, and `blender` tools behind the existing permission, approval, audit, timeout, and untrusted-result handling. Blender supports create_model, edit_model, render, export, and verify intents. Voice now resolves an explicitly configured `BOBAI_VOICE_PROVIDER_URL` before local/echo fallbacks, while image, video, music, design, computer, and other provider boundaries are represented consistently in configuration. The tool router prefers research for current, changing, niche, disputed, or externally verifiable factual claims and uses execution tools when the user asks BobAI to actually operate software or create an artifact. The chat system policy rejects reflexive agreement and empty praise, corrects unsupported premises, distinguishes fact/inference/uncertainty, reacts naturally to emotional context without pretending to possess human feelings, treats external content as untrusted, and requires result verification before completion claims.

The production training stack has two model lanes. `bob-0.2-native` remains the tiny byte-level laptop/dev sanity model. `bob-production` is a separate from-scratch scalable Transformer using RoPE, RMSNorm, SwiGLU, grouped-query attention, PyTorch scaled-dot-product attention/Flash Attention where supported, tied embeddings, optional gradient checkpointing, a trainable byte-level BPE tokenizer, mixed precision, gradient accumulation, cosine warmup/decay, resumable checkpoints, validation, and torchrun/DDP multi-GPU training. Production profiles are provided from a small dev configuration through 125M, 350M, 1.3B, and 3B-class configurations. The production trainer now has explicit pretraining and instruction stages, deterministic raw-text preparation, checkpoint weight transfer, and production evaluation. `model-training/pipeline.py` is the one-command orchestration entry point after upstream terms are reviewed. The Node runtime can automatically use the production model when artifacts exist and can launch a bounded configurable local worker pool.

The training corpus boundary now includes streamed FineWeb-Edu English and selected FineWeb-2 multilingual configurations, including strong Hindi and Telugu coverage plus other Indian and international languages, with deterministic hashing/deduplication and provenance. The corpus builder requires explicit upstream-terms confirmation because CommonCrawl/ODC-By conditions apply. Private chat history is never automatically ingested. Instruction/capability data continues to include coding, UI/UX design, research, tools, memory, security, multilingual behavior, voice, media, Paint, Blender/3D, recovery, verification, and teacher-distillation traces. Multimodal assets remain manifest-driven and rights-filtered rather than being silently embedded in the Git repository.
