# BobAI handoff — 2026-09-11

This handoff records the current repository state after the latest repository-only implementation pass. BobAI is the general AI platform, with a TypeScript and Node.js Express API, PostgreSQL and Drizzle persistence, pgvector groundwork, and a Next.js/React application. Bob is the user-facing manager, with Alex, Ben, Ryan, and Violet representing the intended internal planning, coding, review, and vision roles.

The repository now has durable conversation lifecycle and revision behavior, pagination and deterministic cursors, offline conflict detection, indexed search, project-scoped instructions and model/tool policy, durable agent queues and lifecycle history, structured planner/coder/reviewer contracts, file version lineage and document retrieval foundations, OCR queue and malware scanning boundaries, memory relevance/provenance/expiration/history foundations, persistent research sessions and citations, generated image history, durable automation and webhook delivery records, security activity, settings persistence, dependency hardening, and user-managed MCP registration and scopes.

MCP registration is backed by the existing integrations table. Authenticated users can register, update, disable, delete, list, discover, approve, and execute MCP tools inside their personal workspace. Scope checks are enforced during discovery, approval, and execution. Production URLs require HTTPS, reject embedded credentials and unsafe ports, and resolve to public addresses before storage and again before outbound calls. This is a defense-in-depth network boundary, not a claim that application-level DNS checks alone can defeat every possible SSRF or DNS-rebinding scenario.

Authentication now has adaptive in-process abuse backoff on top of fixed rate limits. Repeated failed login and MFA attempts temporarily increase blocking time, successful authentication clears the failure record, and stale records are pruned. The retention path now purges direct user-owned operational records and dependent conversation, memory, file, index, webhook, tool, automation, agent, notification, media, research, settings, and credential records before the final user row is removed after its deletion grace period. Billing records are intentionally not blindly purged because they can have separate retention obligations.

Long-context chat preparation now performs model-backed compaction when the conversation crosses the compaction threshold. Older turns are summarized under an explicit instruction to treat conversation material as untrusted data, recent turns are preserved, and a bounded extractive fallback is used if the summarizer cannot run. This is application code, but the last user-confirmed local build predates the change, so the async preparation path remains unverified until the laptop build phase.

The research service now ranks normalized sources using query relevance, freshness, and a bounded domain-credibility heuristic, deduplicates equivalent URLs more aggressively, and caches public search results briefly in process to reduce repeated provider calls. Deep research already isolates fetched web content as untrusted evidence before synthesis. These controls improve the pipeline without pretending that a heuristic source score is a substitute for human or domain-specific credibility review.

The remaining repository-only work is now concentrated on deeper memory merge/conflict semantics and privacy classification, complete export/deletion proofs, richer research replay and claim mapping, project export/import, complete action confirmation and idempotency coverage, connector authorization contracts, stronger agent cancellation and diff validation, and test coverage. A real disposable coding sandbox with filesystem, command, process, CPU, memory, and time enforcement remains blocked until an actual isolated executor runtime exists and can be verified.

External search credentials, production media providers, durable object storage, production email, deployment secrets, production model credentials, OAuth credentials, and the isolated coding runtime remain environment-dependent. They are not marked complete merely because their interfaces exist. Post-change build, API smoke, browser, provider, and sandbox verification belongs to the later laptop/environment phase after the major repository work is finished.

Before every future commit, roadmap.md and this handoff must both be updated. roadmap.md must remain checklist-only. This handoff must remain paragraph-only and must explicitly state what was added, what is implemented, and what is next. Unverified environment, provider, deployment, hardware, and runtime work must remain blocked rather than being called complete.
