# BobAI handoff — 2026-09-13

The repository now has the public Bob model family names Bob, Forge, Vanta, Echo, Flux, and Vector, with Bob Core and runtime identifiers kept internal. Normal users do not receive scheduler or runtime registry state through ordinary model APIs; the runtime inspection surface remains behind the existing admin boundary.

The runtime layer now has a single resource-aware lifecycle manager for the central text profiles and the specialist capability set. Bob and Forge share the native model with reference-counted loading so concurrent requests cannot unload the underlying artifact. Specialist workers are local loopback processes with per-worker bearer tokens, lazy checkpoint loading, bounded request bodies, and shutdown handling. Vector can consume the trained embedding checkpoint when available while preserving the deterministic fallback before training. Vanta vision can consume its local checkpoint and returns an explicit unavailable state before training rather than pretending a vision model exists.

A specialist dataset preparation CLI has also been added so eligible local text pairs, image folders, audio transcripts, TTS inputs, and multimodal records can be converted into the tensor contracts expected by the specialist trainer. Root npm scripts expose specialist preparation and local serving alongside the existing Bob training commands. The current specialist worker supports the exported PyTorch checkpoint formats for embeddings, reranking, vision, ASR, TTS, and image generation, but target-quality behavior still depends on real datasets and training.

The remaining work is deliberately the boundary between repository implementation and real execution. Speech request preprocessing and synthesis need their final API wiring, image generation needs its trained-model path wired into the media route, retrieval and agent execution need full lease coverage, and BobHS still needs durable production scheduling, ingress, shared state, persistence, multi-node coordination, deployment, backups, and failover hardening. Target Windows builds, real training, codec support, end-to-end verification, security/load testing, and performance measurement require the user's environment and must not be falsely marked complete.

Before every future commit, roadmap.md and this handoff must both be updated. roadmap.md remains checklist-only and this handoff remains paragraph-only. The goal is to finish all repository-side execution and orchestration boundaries first, leaving only genuine environment-dependent work for the training and verification phase.
