# BobAI handoff — 2026-09-13

This pass makes the model family naming explicit and keeps internal orchestration separate from the normal user surface. The public model names are Bob for the main assistant, Forge for coding, Vanta for vision and retrieval reranking, Echo for speech, Flux for image generation, and Vector for embeddings. The runtime identifiers remain implementation details so model artifacts can evolve without exposing internal service names.

Bob Core is an internal orchestration concept, not a normal-user feature. Runtime inspection and task-plan inspection are now mounted under the authenticated admin area, while ordinary authenticated users do not receive the runtime registry or scheduler state through the normal model endpoint. The runtime manager already tracks capability, priority, memory budget, active requests, loading state, idle eviction, and task planning. The remaining integration work is wiring that manager into every actual execution path rather than treating the registry as a UI feature.

Bob-0.2-native remains the central from-scratch text model. The specialist training kit remains available for Vector, Vanta, Echo, and Flux research-scale architectures, with training artifacts kept out of git. The target Windows laptop is still the training and runtime verification boundary. A real training run still depends on the user's eligible dataset, available disk space, RAM, CPU time, and environment setup, so repository work must not pretend those weights already exist.

BobMedia remains a native boundary with in-process integrations and no child-process fallback. The current media core still intentionally covers PCM16 WAV only. Broader codecs, native library linkage, actual model weights, and performance remain target-machine work. BobHS remains the worker/controller foundation and still needs production ingress, shared durable scheduling state, persistence, multi-node coordination, deployment, backups, and external verification before it can be called production-complete.

Before every future commit, roadmap.md and this handoff must both be updated. roadmap.md remains checklist-only and this handoff remains paragraph-only. The next code-side priority is wiring automatic runtime selection and leasing through the actual execution paths, then the remaining environment-dependent verification can begin alongside the user's training runs.
