# BobAI handoff — 2026-09-11

This handoff records the current repository state after another code-side pass. BobAI is the general AI platform, with the API built on TypeScript, Node.js, Express, PostgreSQL, Drizzle, and pgvector groundwork, plus a Next.js/React web application. Bob is the user-facing manager, while Alex, Ben, Ryan, and Violet represent the intended internal planning, coding, review, and vision roles.

The repository now includes durable conversation revisions, restoration, archive/restore, pagination, deterministic cursors, offline conflict detection, indexed search, project-scoped instructions and tool/model policy, durable agent queues and lifecycle history, structured planner/coder/reviewer contracts, file version lineage, project-aware document indexing and search, OCR queue groundwork, malware scanning boundaries, memory relevance/provenance/expiration/history foundations, persistent research sessions and citations, generated image history, durable automation and webhook delivery records, security activity, settings persistence, and hardened dependency configuration.

The MCP subsystem now has a user-managed registry backed by the existing integrations table. Authenticated users can register, update, disable, delete, list, discover, approve, and execute MCP tools within their personal workspace. Stored scopes are enforced during discovery, approval, and execution. MCP URLs are checked at registration and again immediately before outbound calls. Production registrations require HTTPS, reject embedded credentials and unsafe ports, and resolve hostnames to public addresses before use. The network check is intentionally defense-in-depth rather than a claim of perfect SSRF prevention.

Authentication now has adaptive in-process abuse controls layered on top of the existing fixed rate limits. Repeated failed login and MFA attempts produce temporary exponential backoff, successful authentication clears the failure state, and the state is bounded and periodically pruned. The account retention path now has a dedicated purge service that removes direct user-owned operational data and dependent records before permanent deletion after the grace period, while deliberately leaving billing/other records that may have separate retention requirements untouched.

Long conversations now use model-backed context compaction when the request exceeds the compaction threshold. Older conversation turns are summarized by the selected BobAI model under an explicit instruction to treat the conversation as untrusted data, then recent turns are retained for the live request. A bounded deterministic fallback is used if the summarizer cannot run. This is real application behavior, but the last user-confirmed local build predates this change, so the new async preparation path must be built locally before it is called verified.

The next code-side targets remain the repository-only pieces that can be implemented without pretending external infrastructure exists. These include stronger memory contradiction/merge handling and privacy classification, broader export coverage and deletion proofs, research source ranking and credibility metadata, research caching/replay/quotas, project export/import, complete destructive-action confirmation and remaining idempotency coverage, connector authorization contracts, stronger agent cancellation and diff validation, and test coverage around all of these paths. A genuine coding sandbox with filesystem, command, process, CPU, memory, and time isolation remains intentionally blocked until a real executor runtime can enforce and verify those boundaries.

No such dependency is being marked complete merely because an abstraction exists.
