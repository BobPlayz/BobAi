# BobAI handoff — 2026-09-12

This pass moved BobAI substantially toward a local-first, zero-provider-key development model. The core and coding model client now defaults to Ollama on 127.0.0.1:11434, with model names defaulting to qwen2.5:3b and external model URLs retained only as optional compatibility overrides. No model API key is required for the local path. The repository still needs the user's local Ollama installation and model weights, so those runtime prerequisites are not claimed as verified here.

Embedding generation no longer depends on an external embedding URL, token, or model variable. BobAI now produces deterministic normalized 1536-dimensional vectors locally using SHA-256-derived term features, matching the existing pgvector dimension contract. This removes provider credentials and network calls from indexing and memory embedding, but it is deliberately a lightweight local fallback rather than a neural semantic embedding model. A stronger local embedding model can be added later without restoring provider credentials.

Web research no longer requires a search-provider URL or API key. The research service now performs bounded HTTPS requests directly to DuckDuckGo's HTML search endpoint, parses result links and snippets, and keeps the existing ranking, credibility, freshness, deduplication, caching, retry, and response-size protections. This is keyless and free at the application level, although it still requires internet access for live search and depends on the public search page remaining available.

Image generation now has a local deterministic SVG renderer. It produces safe, bounded, prompt-labelled abstract artwork entirely inside BobAI and persists it through the existing image-history path. This is a genuine local renderer, not an AI diffusion model, and it does not pretend to provide photorealistic generation. Local video generation remains intentionally unavailable until a real local video model/runtime exists; BobAI returns an explicit error instead of fabricating a video result.

The capability system now has real local implementations for diagram generation and sketch-to-UI specification. Diagram requests produce Mermaid flowchart code from the supplied description, while sketch-to-UI requests produce a structured HTML/CSS-style component specification. Other advanced image editing, video, talking-avatar, face-swap, speech, transcription, and music capabilities still support optional external compatibility providers in code but no longer require their provider variables to exist in the standard environment templates. They remain unimplemented locally where a real model or specialized runtime is required.

The root and API environment templates were reduced accordingly. External capability-provider URL/key pairs, embedding-provider settings, local-media-provider URL/path settings, upload-provider settings, notification-provider settings, and separate image/video/voice/music/design provider settings were removed from the templates. Social OAuth credentials remain because Google, GitHub, and Apple control their own identity systems and cannot be recreated inside BobAI. Optional SMTP settings remain only for real external email delivery; development already has local OTP delivery that logs the code when SMTP is absent.

The current repository therefore has a much smaller provider surface: local Ollama can handle the primary AI path, local deterministic embeddings handle vector creation, direct web search handles research without a search API credential, BobMail handles SMTP protocol logic when a mail server is supplied, and BobAI itself handles local diagrams, UI specifications, and deterministic image rendering. The remaining external dependencies are not being hidden: social identity providers, a real SMTP mail server for actual email delivery, PostgreSQL unless a local database is installed, model weights/runtime hardware, and specialized local media/speech runtimes still require environment or machine-level setup.

Before every future commit, roadmap.md and this handoff must both be updated. roadmap.md must remain checklist-only and this handoff must remain paragraph-only. Unverified build, test, provider, deployment, runtime, hardware, and environment work must never be represented as completed merely because the repository contains the corresponding implementation.
