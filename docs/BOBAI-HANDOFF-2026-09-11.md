# BobAI handoff — 2026-09-12

The latest runtime log exposed two separate auth issues. Google returned “Google sign-in is not configured” because the provider credentials are absent from the user's environment. The Google button is already a real OAuth authorization-code + PKCE flow, but a real provider login requires a registered OAuth client and secret plus the BobAI callback URL. The same requirement applies to GitHub and Apple. Provider credentials must not be invented or committed.

The runtime log also exposed a real code/schema mismatch in email OTP recovery. The OTP service uses a purpose field to distinguish login OTPs from verification OTPs, but the user's database had not received migration 0026, so PostgreSQL produced `and  = $2` and failed with a syntax error. The Drizzle schema definition also lacked that purpose field. The schema is now corrected, and the development launcher now applies pending migrations before starting API and web, so `npm run ai` will not intentionally start against a stale repository schema.

Migration 0026 already contains the required `ALTER TABLE email_otps ADD COLUMN IF NOT EXISTS purpose text NOT NULL DEFAULT 'verification'` and its index, so no duplicate migration was added. The next `npm run ai` should apply 0026 before the API starts. The repository-side fix is complete, while the actual database migration still has to execute in the user's environment, which the launcher now performs automatically.

Social authentication remains real provider OAuth. Clicking Google, Apple, or GitHub sends the browser to the provider's actual authorization endpoint, where an existing provider session can be selected or used. The server then validates the returned identity before issuing a BobAI session. If provider credentials are missing, the API correctly refuses the flow rather than pretending the user authenticated.

The auth UI is consolidated into one compact page. Sign-in, account creation, email verification, passwordless email-code recovery, and MFA are modes inside one card. The provider controls are small icon buttons, and `/signup` plus `/verify-otp` redirect into the same auth surface.
