# BobAI handoff — 2026-09-11

This handoff records the current repository state after the latest code-side implementation pass. BobAI is the general AI platform, with a TypeScript and Node.js Express API, PostgreSQL and Drizzle persistence, pgvector groundwork, and a Next.js/React application. Bob is the user-facing manager, while Alex, Ben, Ryan, and Violet represent the intended internal planning, coding, review, and vision roles.

The repository now includes durable conversation lifecycle and revision behavior, pagination and deterministic cursors, offline conflict detection, indexed search, project-scoped instructions and model/tool policy, authenticated project export/import, durable agent queues and lifecycle history, structured planner/coder/reviewer contracts, file version lineage and document retrieval foundations, OCR queue and malware scanning boundaries, memory relevance/provenance/expiration/history foundations, persistent research sessions and citations, generated image history, durable automation and webhook delivery records, security activity, settings persistence, dependency hardening, user-managed MCP registration and scopes, adaptive authentication abuse backoff, account purge handling, model-backed long-context compaction, ranked/cached research results, and database-backed idempotency for costly action routes.

Memory handling has now gained a real privacy classification and contradiction signal. New memories are classified as sensitive, personal, technical, or preference, while sensitive secrets continue to be rejected. When a new memory conflicts with another active memory in the same scoped category, the records are linked through bounded contradiction metadata and the conflicting memories receive reduced confidence instead of one silently replacing the other. Memory retrieval now includes confidence in relevance scoring, and memory history snapshots preserve metadata.

The action-idempotency layer is durable and bounded. Completed responses can be replayed, a key cannot be reused for a different request payload, abandoned processing claims expire, oversized responses are not persisted, and maintenance removes expired or abandoned records. Image generation, automation execution, and MCP execution use it. MCP argument-size validation happens before consuming the one-time approval token.

The project subsystem supports authenticated project export and import. Export contains project configuration plus the user's own project-file metadata and extracted text, while import is bounded by file count, text size, and workspace authorization. It intentionally does not claim to export arbitrary external object-storage bytes because durable production object storage remains environment-dependent.

MCP registration is backed by the existing integrations table. Authenticated users can register, update, disable, delete, list, discover, approve, and execute MCP tools inside their personal workspace. Scope checks are enforced during discovery, approval, and execution. Production URLs require HTTPS, reject embedded credentials and unsafe ports, and resolve to public addresses before storage and again before outbound calls. This is defense-in-depth rather than a claim that application-level DNS checks alone defeat every SSRF or DNS-rebinding scenario.

Authentication has adaptive in-process abuse backoff on top of fixed rate limits. Repeated failed login and MFA attempts temporarily increase blocking time, successful authentication clears the failure record, and stale records are pruned. The retention path has a dedicated purge service that removes direct user-owned operational records and dependent conversation, memory, file, index, webhook, tool, automation, agent, notification, media, research, settings, and credential records before final deletion after the grace period. Billing records remain intentionally outside the generic purge because they can have separate retention obligations.

Long-context chat preparation performs model-backed compaction when a conversation crosses the compaction threshold. Older turns are summarized under an explicit instruction to treat conversation material as untrusted data, recent turns are preserved, and a bounded extractive fallback is used if the summarizer cannot run. The research service ranks sources using query relevance, freshness, and bounded domain credibility heuristics, deduplicates equivalent URLs, and briefly caches public search results in process. Deep research isolates fetched web content as untrusted evidence before synthesis.

The remaining repository-only work is concentrated on complete export/deletion proofs, richer memory merge/conflict workflows and privacy controls, research claim-to-source mapping and replay collections, strict per-tool schema enforcement in every executor path, broader destructive-action confirmation coverage, connector authorization contracts, stronger agent cancellation and diff validation, and tests for the new reliability/security paths. A genuine disposable coding sandbox with filesystem, command, process, CPU, memory, and time enforcement remains blocked until an actual isolated executor runtime exists and can be verified.

External search credentials, production media providers, durable object storage, production email, deployment secrets, production model credentials, OAuth credentials, and the isolated coding runtime remain environment-dependent. They are not marked complete merely because their interfaces exist. Post-change build, API smoke, browser, provider, and sandbox verification belongs to the later laptop/environment phase after the major repository work is finished.
