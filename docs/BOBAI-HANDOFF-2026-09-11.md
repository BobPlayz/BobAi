# BobAI handoff — 2026-09-12

The latest runtime log exposed two auth issues. Google returned “Google sign-in is not configured” because provider credentials are absent from the user's environment. The Google button is already a real OAuth authorization-code + PKCE flow, but a real provider login requires a registered OAuth client and secret plus the BobAI callback URL. The same requirement applies to GitHub and Apple. Provider credentials must not be invented or committed.

The runtime log also exposed a real code/schema mismatch in email OTP recovery. The OTP service uses a purpose field to distinguish login OTPs from verification OTPs, but the user's database had not received migration 0026, so PostgreSQL produced `and  = $2` and failed with a syntax error. The Drizzle schema definition was corrected, and the development launcher now applies pending migrations before starting API and web, so `npm run ai` does not intentionally start against a stale repository schema.

BobMail now replaces the Resend runtime integration. It is an in-repository SMTP client using Node's built-in networking and TLS support, with implicit TLS on port 465, STARTTLS when offered on other ports, optional SMTP AUTH PLAIN credentials, bounded connection timeouts, safe address extraction, header encoding, dot-stuffing, OTP delivery, and password-reset delivery. The implementation refuses to send SMTP credentials over a non-TLS connection and correctly handles multiline EHLO capability responses.

Resend is no longer used by the application and its environment variables have been removed from the templates. The API production validator now requires SMTP host, port, and sender configuration and validates optional username/password pairing. The API package manifest no longer declares Resend; the existing lockfile still contains its historical package records and has not been regenerated in this repository-only pass, so dependency-lock/build verification remains unverified.

The environment templates were cleaned of the obsolete BOBDB_URL and Resend variables and now expose the five BobMail settings needed for normal SMTP delivery: host, port, user, password, and sender. Capability-provider variables remain because they correspond to separately optional BobAI capabilities, while provider credentials that are not configured can remain blank. The repository cannot remove secrets or unrelated variables from the user's private local `.env` because that file is not committed to GitHub.

Social authentication remains real provider OAuth. Clicking Google, Apple, or GitHub sends the browser to the provider's actual authorization endpoint, where an existing provider session can be selected or used. The server then validates the returned identity before issuing a BobAI session. If provider credentials are missing, the API correctly refuses the flow rather than pretending the user authenticated.

The auth UI is consolidated into one compact page. Sign-in, account creation, email verification, passwordless email-code recovery, and MFA are modes inside one card. The provider controls are small icon buttons, and `/signup` plus `/verify-otp` redirect into the same auth surface.

The remaining unchecked work is genuinely environment or external-system dependent: Google, Apple, and GitHub OAuth client registration and secrets, callback registration, SMTP server credentials and real email delivery, object storage/search/media configuration, hosting/DNS, model weights, Docker runtime deployment, retention and backup proof, security monitoring, external load or penetration verification, provider connectivity, browser verification, sandbox end-to-end execution, dependency-lock regeneration/verification, and final API smoke verification. Repository implementation has not been represented as externally verified merely because the code exists.
