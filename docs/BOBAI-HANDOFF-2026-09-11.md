BobAI continues to present one user-facing native model rather than separate named model personalities. The same model decides whether to answer directly or request tools, while the tool registry remains an independent policy boundary for permissions, approvals, validation, provider availability, and bounded execution.

The chat path runs a bounded model-tool loop: Bob selects tools, approved tools execute through a centralized executor registry, tool results are returned as untrusted data to the same model, and Bob can select another tool or produce the final response. Every currently registered tool has a repository-side executor entry. Approval-required tools stop before execution unless a valid short-lived approval is supplied. Provider adapters enforce HTTPS in production, timeouts, bounded streaming response reads, and redirect rejection. Browser and website-test targets reject embedded credentials and hosts or resolved addresses in private or link-local ranges. Multiple approval-required actions cannot be bundled into one model decision, preventing one approval token from authorizing a batch of separate high-impact actions. Tool execution outcomes are recorded through the existing sanitized audit service.

The user-facing chat path explicitly pins response and tool routing to Bob, and the environment templates expose one main model configuration without obsolete separate coding-model or old specialist-name variables. BOBAI_TOOLS_ENABLED provides a repository-wide execution disable control and the router fails closed when it is disabled. Background agent responses expose Bob plus requested capabilities rather than old employee identities, and the old vision service filename/API identity has been replaced with a capability-neutral vision analysis service. Running agent cancellation now propagates into the active execution controller so cancelling a running job stops the controller before another execution step can begin. Production administrator validation accepts one or more distinct valid configured administrator addresses. Training dataset preparation now requires the exact approved conversation consent scope and has regression coverage for that privacy boundary. Automation tool execution resolves and runs the requested workspace-owned automation directly instead of turning an automation ID into a generic coding-agent task. Remaining user-visible legacy vision/image labels are capability-neutral, and automation provider responses use the same bounded streaming HTTP safety layer.

The central tool registry now supports explicit enum constraints for operation-like inputs, with voice restricted to its implemented operations. MCP response bodies use the same bounded streaming reader instead of an unbounded response.text call. Model bundle manifests reject duplicate file names and enforce a bounded aggregate size. Native audio entry points validate PCM16 WAV structure, supported sample rates, channel count, and a 15-minute duration limit before native resampling or inference, preventing pathological WAV metadata from causing excessive native allocations.

The repository does not claim that every real provider/local adapter has been verified, nor that the unified model has been trained to a production-quality level. Final datasets, long-running training, real provider verification, target hardware and native-media builds, production transport/database wiring, external security and failure testing, multi-worker target-environment verification, and final release validation remain environment-dependent.
