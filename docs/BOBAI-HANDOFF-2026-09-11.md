# BobAI handoff — 2026-09-13

The repository now has the public Bob model family names Bob, Forge, Vanta, Echo, Flux, and Vector, with Bob Core and runtime identifiers kept internal. Normal users do not receive scheduler or runtime registry state through ordinary model APIs; the admin runtime surface remains protected by the existing admin middleware.

The runtime layer now has a single resource-aware lifecycle manager for the central text profiles and the specialist capability set. Bob and Forge share the native model with reference-counted loading so concurrent requests cannot unload the underlying artifact. Specialist workers are local loopback processes with per-worker bearer tokens, lazy checkpoint loading, bounded request bodies, and shutdown handling. Vector can consume the trained embedding checkpoint when available while preserving the deterministic fallback before training. Vanta vision can consume its local checkpoint and reports explicitly when the model is not yet available. Flux image generation now uses the local specialist checkpoint when it exists and retains the deterministic renderer before training.

A specialist dataset preparation CLI converts eligible local text pairs, image records, audio transcripts, TTS inputs, and multimodal records into the tensor contracts expected by the specialist trainer. Root npm scripts expose specialist preparation and local serving alongside the existing Bob training commands. The local specialist worker boundary covers the exported PyTorch checkpoint formats for embeddings, reranking, vision, ASR, TTS, and image generation. Audio feature helpers are included for PCM16 WAV preparation and the specialist ASR path.

Code-side work is intentionally separated from target-machine verification. The remaining unchecked work concerns complete speech API wiring, full runtime lease coverage across retrieval and agents, target Windows native media builds, actual model training, broader codecs, production BobHS persistence and ingress, final end-to-end verification, security/load testing, and performance. Those cannot honestly be marked complete from repository inspection alone.

Before every future commit, roadmap.md and this handoff must both be updated. roadmap.md remains checklist-only and this handoff remains paragraph-only. The goal is to finish all repository-side execution and orchestration boundaries first, leaving only genuine environment-dependent work for the training and verification phase.
