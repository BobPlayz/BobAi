# BobAI handoff — 2026-09-11

This handoff records the current repository state after the latest code-side implementation pass. BobAI is the general AI platform, with a TypeScript and Node.js Express API, PostgreSQL and Drizzle persistence, pgvector groundwork, and a Next.js/React application. Bob is the user-facing manager, while Alex, Ben, Ryan, and Violet represent the intended internal planning, coding, review, and vision roles.

The repository now includes durable conversation lifecycle and revision behavior, pagination and deterministic cursors, offline conflict detection, indexed search, project-scoped instructions and model/tool policy, authenticated project export/import, durable agent queues and lifecycle history, structured planner/coder/reviewer contracts, file version lineage and document retrieval foundations, OCR queue and malware scanning boundaries, memory relevance/provenance/expiration/history foundations, privacy classification and contradiction signals, persistent research sessions and citations, generated image history, durable automation and webhook delivery records, security activity, settings persistence, dependency hardening, user-managed MCP registration and scopes, adaptive authentication abuse backoff, account purge handling, model-backed long-context compaction, ranked/cached research results, durable idempotency for costly action routes, and an optional PostgreSQL-backed distributed rate limiter.

The rate limiter can now use the existing PostgreSQL database for atomic IP and user buckets when BOBAI_DISTRIBUTED_RATE_LIMIT=true. The local in-process limiter remains the default and is used as a fallback if the database limiter cannot be reached. Expired distributed buckets are removed by maintenance. This gives production deployments a multi-process rate-limit path without adding another runtime dependency, while still requiring real deployment testing before it is considered operationally verified.

The action-idempotency layer is durable and bounded. Completed responses can be replayed, a key cannot be reused for a different request payload, abandoned processing claims expire, oversized responses are not persisted, and maintenance removes expired or abandoned records. Image generation, automation execution, and MCP execution use it. MCP argument-size validation happens before consuming the one-time approval token.

The memory subsystem classifies new memory as sensitive, personal, technical, or preference, rejects sensitive secrets, links conflicting active memories within the same scoped category, lowers confidence when a contradiction is detected, and includes confidence in retrieval scoring. Memory history snapshots preserve metadata.

The project subsystem supports authenticated project export and import. Export contains project configuration plus the user's own project-file metadata and extracted text, while import is bounded by file count, text size, and workspace authorization. It intentionally does not claim to export arbitrary external object-storage bytes because durable production object storage remains environment-dependent.

The embedding provider boundary requires HTTPS outside local development, rejects embedded credentials and fragments, disables redirects, bounds responses, enforces timeouts, and validates the expected finite vector dimensions. The research service ranks sources using query relevance, freshness, and bounded domain credibility heuristics, deduplicates equivalent URLs, and briefly caches public search results. Deep research isolates fetched web content as untrusted evidence before synthesis.

The remaining repository-only work is concentrated on complete export/deletion proofs, richer memory merge/update/conflict workflows and user controls, research claim mapping and replay collections, strict per-tool result limits in every executor path, connector authorization contracts, stronger agent cancellation and diff validation, and broader automated tests. A genuine disposable coding sandbox with filesystem, command, process, CPU, memory, and time enforcement remains blocked until an actual isolated executor runtime exists and can be verified.

External search credentials, production media providers, durable object storage, production email, deployment secrets, production model credentials, OAuth credentials, and the isolated coding runtime remain environment-dependent.
