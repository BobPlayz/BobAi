# BobAI handoff — 2026-09-11

This handoff records the current repository state after the latest code-side collaboration and executor-security implementation. BobAI is the general AI platform, with a TypeScript and Node.js Express API, PostgreSQL and Drizzle persistence, pgvector groundwork, and a Next.js/React application. Bob is the user-facing manager, while Alex, Ben, Ryan, and Violet represent the intended internal planning, coding, review, and vision roles.

The repository now includes durable conversation lifecycle and revision behavior, pagination and deterministic cursors, offline conflict detection, indexed search, project-scoped instructions and model/tool policy, authenticated project export/import, conversation folders and labels, durable agent queues and lifecycle history, structured planner/coder/reviewer contracts, file version lineage and document retrieval foundations, OCR queue and malware scanning, memory relevance/provenance/expiration/history foundations, privacy classification and contradiction signals, persistent research sessions and citations, generated image history, durable automation and webhook delivery records, security activity, settings persistence, dependency hardening, user-managed MCP registration and scopes, adaptive authentication abuse backoff, account purge handling, model-backed long-context compaction, ranked/cached research results, durable idempotency for costly action routes, optional PostgreSQL-backed distributed rate limiting, hardened embedding-provider validation, and coding-agent timeout/diff handling.

Workspace collaboration is implemented at the API and persistence layer. Workspace members can be listed and managed under a role hierarchy, administrators can create and revoke expiring invitation tokens, invitees must authenticate with the invited email address before acceptance, and membership changes are auditable. File sharing is persisted separately with per-user read/write permission records, requires workspace membership, supports listing and revocation, exposes shared-file discovery, and provides an authenticated shared-download path. The file-share authorization checks the file's actual workspace rather than assuming a personal workspace.

The tool executor now evaluates the authenticated workspace member's role and explicit permission grants before an executable tool can become ready. Owners and admins have full tool permission, viewers and members receive read access by default, and non-read permissions require explicit grants unless the member is privileged. Approval tokens remain bound to user, workspace, and tool and are atomically consumed.

The file upload path has been rechecked against the actual main branch. Uploads are scanned before object storage, production scanning fails closed when the scanner is unavailable, scanner responses are bounded and schema-checked, and the upload response no longer falsely claims indexing has already completed. Indexing and OCR are explicitly reported as queued or pending. Stored-file downloads are bounded by the application file-size limit.

The account export covers a broad set of user-owned operational records, including memory history, project files, tool logs, workspace memberships, webhook delivery history, usage records, and audit records. Credential-bearing fields such as integration encrypted credentials and webhook secrets/headers are intentionally excluded from the portable export. Permanent deletion purges direct operational records while retaining records that may have separate legal or security retention obligations.

The action-idempotency layer is durable and bounded. Completed responses can be replayed, a key cannot be reused for a different request payload, abandoned processing claims expire, oversized responses are not persisted, and maintenance removes expired or abandoned records. Image generation, automation execution, and MCP execution use it. MCP argument-size validation happens before consuming the one-time approval token. An optional PostgreSQL-backed distributed limiter provides atomic IP/user buckets for multi-process deployments, with local fallback and maintenance cleanup.

The coding-agent boundary requests cancellation from the localhost bridge after a hard timeout and validates optional returned diffs for bounded size and basic patch structure before accepting the structured result. This is validation and cancellation signaling, not a claim of genuine filesystem/process isolation. Production still requires a real sandbox-attestation mechanism and executor enforcement.

The memory subsystem classifies new memory as sensitive, personal, technical, or preference, rejects sensitive secrets, links conflicting active memories within the same scoped category, lowers confidence when a contradiction is detected, and includes confidence in retrieval scoring. Memory history snapshots preserve metadata. The embedding provider boundary requires HTTPS outside local development, rejects embedded credentials and fragments, disables redirects, bounds responses, enforces timeouts, and validates the expected finite vector dimensions.

MCP registration is backed by the existing integrations table. Authenticated users can register, update, disable, delete, list, discover, approve, and execute MCP tools inside their personal workspace. Scope checks are enforced during discovery, approval, and execution. Production URLs require HTTPS, reject embedded credentials and unsafe ports, and resolve to public addresses before storage and again before outbound calls. This is defense-in-depth rather than a claim that application-level DNS checks alone defeat every SSRF or DNS-rebinding scenario.

The remaining repository-only work is concentrated on complete deletion proof across every remaining table/storage layer, richer memory merge/update/conflict workflows, research claim mapping and replay collections, strict per-tool result limits in every executor path, connector authorization contracts, full agent dependency/budget/checkpoint behavior, and broader automated tests. A genuine disposable coding sandbox with filesystem, command, process, CPU, memory, and time enforcement remains blocked until an actual isolated executor runtime exists and can be verified.
