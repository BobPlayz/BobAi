# BobAI handoff — 2026-09-12

This pass completes the repository-side migration away from Ollama by advancing the native model to Bob-0.2-native. Bob-0.2-native is a configurable decoder-only transformer trained from scratch, with a 261-token UTF-8 byte tokenizer, configurable context, width, depth, attention heads, feed-forward width, AdamW training, gradient clipping, CPU/CUDA selection, validation loss reporting, and the portable model.bob v2 format. The Node runtime now reads the model architecture from the model header instead of assuming the old one-layer dimensions, performs causal attention directly in Node.js, applies temperature/top-k/top-p sampling and repetition control, and exposes the same native model contract to chat and coding profiles. No Ollama process, URL, environment variable, or fallback inference server is part of this path.

The native training kit remains intentionally source-first. The repository contains the architecture and lifecycle commands, but the small checked-in dataset is only a development proof. A genuinely capable Bob model requires a much larger eligible dataset and real training compute. The dataset path remains governed by explicit eligibility and consent, secret and PII sanitization, deterministic deduplication, and held-out evaluation. Model weights remain deployment artifacts and are not committed to the repository.

The media architecture was also moved toward the requested BobAI-owned runtime boundary. BobMedia is now a Node-API native addon contract rather than a TypeScript wrapper around child processes. BobVoice calls the Piper C API in-process, BobWhisper calls the whisper.cpp C API in-process, and BobMedia performs native PCM16 WAV probing without spawning Piper, whisper-cli, FFmpeg, or a shell. The native addon returns synthesized WAV data directly to Node and performs Whisper resampling internally. The repository includes a node-gyp build contract and target-machine setup documentation. The current native media core deliberately accepts PCM16 WAV for transcription/probing; broad MP3, MP4, WebM, and other codec support still needs to be implemented through an in-process codec library integration rather than reintroducing executable spawning.

The environment templates no longer configure Piper, Whisper, or FFmpeg executable commands. They configure model/library locations for the native media addon instead. The normal TypeScript CI build does not build the native media addon because the target machine's native libraries and model weights are deployment artifacts. The target Windows machine therefore remains a required verification boundary for building the addon, loading the native libraries, and running real speech/media workloads.

The latest repository CI verification point before this media/model pass had npm audit, TypeScript build, tests, and database generation passing after the email OTP and social OAuth fixes. Any new CI run triggered by this pass must be treated as the verification point for these changes before claiming a green post-change build. The native C++ addon is intentionally outside the normal CI build until its target native dependencies are supplied.

BobHS remains repository-foundation code and still needs production ingress/TLS, durable shared controller state, capacity-aware scheduling, persistent volumes, registry integration, rolling deployment behavior, logs, backups, domains, and verified failover before those capabilities can be called production-complete. The same rule applies to real SMTP, social-provider callbacks, sandbox runtime verification, model training, native media verification, and target-hardware performance. Before every future commit, roadmap.md and this handoff must both be updated. roadmap.md remains checklist-only and this handoff remains paragraph-only.
