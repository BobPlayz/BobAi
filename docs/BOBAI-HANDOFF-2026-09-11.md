# BobAI handoff — 2026-09-13

This pass continues the internal model orchestration work. Normal users see the public family names Bob, Forge, Vanta, Echo, Flux, and Vector, while Bob Core and runtime identifiers remain internal implementation details. The admin runtime endpoint is the only normal API surface that exposes scheduler state, and it remains protected by the existing admin middleware.

The runtime manager now supports the specialist capability set and can lazily start a local specialist worker when its trained artifact exists. The worker is loopback-only, uses a per-process bearer token, is created on demand, and is stopped through the runtime lifecycle. Native Bob and Forge still share the native model safely through reference counting, so one profile cannot unload the model while another request is using it. Vector embedding calls can use the trained specialist when its artifact is present and otherwise retain the deterministic pre-training fallback. Vanta vision calls now use the same local specialist boundary when trained and report clearly when the model is not yet available.

The specialist training kit now has a local Python worker boundary that can load the exported PyTorch checkpoints for embedding, reranking, vision, ASR, TTS, and image inference. Pillow is included for the image boundary. The worker is deliberately a local execution adapter, not a hosted AI provider. Training artifacts remain outside git and still require the user's real eligible datasets and Windows environment.

Code-side work is intentionally separated from target-machine verification. The remaining unchecked work concerns real training, actual checkpoint availability, target Windows native media builds, broader codec support, production BobHS persistence and ingress, final end-to-end verification, and performance. Those cannot honestly be marked complete from repository inspection alone.

Before every future commit, roadmap.md and this handoff must both be updated. roadmap.md remains checklist-only and this handoff remains paragraph-only. The next code-side work should finish the remaining speech/image execution adapters and BobHS production scheduling boundaries; after that, the repository should be ready for the user's environment-dependent training and verification phase.
