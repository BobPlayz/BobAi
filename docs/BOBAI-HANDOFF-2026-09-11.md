This handoff records the current repository state after the latest code-side pass. The project is BobAI, a general AI platform with chat, memory, files, research, media, projects, tools, automation, MCP, and agent subsystems. The API uses TypeScript, Node.js, Express, PostgreSQL, Drizzle, and pgvector groundwork, while the web application is Next.js/React. The repository now contains the large reliability and security pass from this project session. Conversation persistence has durable revisions, restoration, archive/restore behavior, pagination, deterministic cursors, offline-sync conflict detection, and indexed search. Projects have scoped instructions, model/tool policy, files, activity, and authorization boundaries. Agent tasks have durable queue state, lifecycle history, recovery, structured planner/coder/reviewer contracts, idempotency protection in the major executable paths, and production attestation gates. File handling has version lineage, project ownership checks, document chunking/indexing, ranked lexical fallback, OCR queue groundwork, authorized downloads, and a malware-scanning boundary. Memory has scoped retrieval, relevance/provenance foundations, expiration handling, immutable history, and maintenance cleanup. Research has normalized persistent sessions and citations. Generated image history is persisted and provider media URLs are validated. Webhooks and automation have durable run/delivery records, replay protection, authenticated management, and scheduling recovery. Settings and security activity APIs are present, and dependency overrides have been hardened.

The current code-side addition is a user-managed MCP registry. MCP servers can now be registered, updated, disabled, deleted, listed, discovered, and permission-scoped per personal workspace. Server URLs are validated before persistence and again before outbound calls. Production registrations require HTTPS, reject URL credentials and unsafe ports, and perform DNS resolution checks that reject loopback, private, link-local, multicast, documentation, and other reserved address ranges. MCP tool discovery and execution enforce the stored server scopes, while the existing short-lived approval token remains bound to the authenticated user and workspace.

This MCP registry deliberately does not pretend to solve every network-level SSRF problem. DNS and network policy are still defense-in-depth controls, and production deployments should place outbound traffic behind a network egress policy. User-managed MCP credentials and OAuth are also not invented here because storing or exchanging third-party secrets needs a real connector authorization design and environment.
